# 设计说明

完整计划见批准的实施计划；本文记录已经落地的设计决策。

## 1. 分层与依赖方向

```
desktop（独立窗口） / cli（cli / cli_materials / cli_common） / web（书架页面、写操作、设置、问答） / experiments
   ↓
job_runner（子进程执行、两条队列） → worker（任务子进程入口） → job_handlers（各类任务的处理）
   ↓
jobs（任务表）  config_edit（改配置）  apphome（书库位置）  credentials（密钥）
   ↓
pipeline（run 流程、extract 整理笔记、integrate 整合、review 总复习、qa 问答、memory 输入预算、organize 移动和删除、
          ingest 资料入库、slides 课件匹配、materials 拆题与知识点对应、scoring 打分、report 考前报告……）
   ↓                                         ↓
books（导出）  knowledge（课程记忆存储）  library（书库）  materials / reports / conversations（资料、报告、问答存储）
asr（FunASR / Qwen3 / 大模型转写、本地模型下载）  archive（压缩包展开）
   ↓
llm.base（统一接口）  course（课程设置）  documents  media  render  textnorm  timecode
   ↑
llm 适配器（anthropic / gemini / openai_compat），由 registry 按配置创建
```

- 流程代码只依赖 `llm.base` 的类型（`LLMProvider`、`TextPart/ImagePart/AudioPart`、`Usage`），不接触任何厂商 SDK。
- 适配器通过 `registry` 延迟导入：没用到的 SDK 不会被加载；新增接入方式只加一个文件和一行注册。
- 同一接入方式下的新模型只改 `config.toml`（模型档案）。

## 2. 结构化输出

- 各家能力不同，由模型档案的 `structured` 决定请求方式：原生 schema（Claude、Gemini）、严格 JSON Schema（GPT）、只保证 JSON 的 `json_object`（DeepSeek、多数通义千问），或把 schema 写进提示词。
- 不管哪种方式，结果统一由基类做 Pydantic 校验；不合格时附上错误信息重试一次，仍失败抛 `StructuredOutputError`（携带已消耗的用量）。
- 截断、拒答、内容过滤属于 `LLMError`，不重试，直接报出原因。
- 输出 schema 的约定：字段全部必填、不设默认值、不用数值范围约束、枚举只用字符串，以兼容最严格的厂商实现。

## 3. 用量与费用

- `Usage.input_tokens` 统一为"含缓存命中"的总输入，`cache_read_tokens` 是其子集。Anthropic 的输入不含缓存部分，适配器会加回去。
- 费用按模型档案里的单价估算；单价为 0 时不估算。

## 4. 语音识别

- **按课程设置选择方案**。课程设置（`course.py`）见第 6 节。录音里只有一种语言时强制使用该语种；几种语言混用或有现场翻译时逐句自动识别。本地模型不支持的语言（如 SenseVoice 只认中英日韩粤）自动改为识别语种，不会报错；地区代码（`zh-tw`）按语言部分处理。
- **本地 FunASR**：
  - 两个预设：SeACo-Paraformer（只认中文，支持热词）和 SenseVoice-Small（中英日韩粤，按课程设置传入语种）。
  - VAD 单段最长 30 秒，输出句级时间戳。
  - 音频由我们读成 float32 数组后再传给 FunASR，避开新版 torchaudio 的文件加载依赖（torchcodec）。
  - SeACo 热词只认中文和数字，按空格切分，最多取 100 个。
  - **切句修复**：FunASR 1.4.16 的 `sentence_info` 会把标点错位 1–2 个字（如"所发，生的效应"）。但整段带标点的文本和逐词时间戳本身是对的（实测 179 个字对 179 个时间戳），所以改为用二者自己重新切句：在句末标点处断开；超过 50 字的长句在逗号处断开。任何一处对不上就退回原结果。
- **Qwen3-ASR**（transformers 原生支持）：用于韩语和中韩混合的课。
  - 先用 fsmn-vad 切成说话片段（老师和翻译之间的停顿就是边界），再逐段识别，每句同时得到文字和语种。
  - 术语表作为 prompt 上下文传入。
  - 不使用 `device_map`（那需要额外安装 accelerate）：先在内存里加载，再整体搬到显卡。
- **大模型转写**：音频按固定时长（默认 10 分钟）切片、转 64kbps 单声道 mp3 后内联发送（OpenAI 兼容接口的 `input_audio` 只收 mp3/wav），逐片转写后加上偏移，拼回整段时间轴。模型同时输出每句的语种；时间缺失或倒退时，取不早于上一句的时间。为适应长课：
  - **分片缓存**：每片结果按型号缓存在工作目录，中断或失败后重跑只请求没完成的片段；损坏的缓存（例如写到一半时任务被取消）当作没有。
  - **拦截的几种表现**（都按拦截处理）：
    - 返回空结果（M2 实测药理学 60–70 分钟这一片连续 3 次为空，且照样计费输入，原样重试无效）；
    - 中转站用一段说明代替结果（M4 实测：Gemini 内容过滤误拦生物学内容时，返回英文说明，finish_reason 为 stop，没有用量）；
    - 输出在中途被截断，带修正提示重试仍不完整；
    - 结果不可用：一半以上的句子是空的或「[听不清]」；或者有现场翻译的课里，清楚的句子有 5 句以上，却没有一句授课语言。M4 实测备用型号会把老师的韩语原话写成「[听不清]」或干脆漏掉，只留下翻译的中文：
      - 全部缓存里，主型号 5147 句只有 1 句「[听不清]」；备用型号 858 句里空句和「[听不清]」占 10.7%，最差的分片 85%；
      - 病毒学的缓存里，主型号 95 片每片都有韩语，备用型号 38 片里 14 片一句韩语都没有；
      - 按这条规则回测全部缓存，主型号没有一片被判为不可用，中文课的备用结果也没有。
      读缓存时也按这个标准，所以重做转写时这类片段会重新处理（最后交给本地模型，至少能转出韩语原文）。
  - **拦截后对半重试、最短片段换型号**：某片被拦截时：
    1. 用主模型按帧对半切开重试，最短切到 2.5 分钟；
    2. 最短的片段仍被拦截，再依次换用 `[asr] llm_alternates` 里的型号（同一档案、同一接口）。
    - M2 实测拦截与型号有关：病毒学第 2 讲 2-2 有一段 30 分钟被 `gemini-3.8-flash-high` 在每一级都拦截，同样的 2.5 分钟片段 `gemini-3-flash`、`gemini-3.5-flash-lite`、`gemini-3.1-flash-lite` 都能转写。
    - 备用模型只用在最短片段上：实测 `gemini-3-flash` 转写 10 分钟的长片段会漏掉大部分内容（同一段只有主模型分片结果的约三分之一字数），转写 2.5 分钟的片段则正常。
    - 结果按成功的型号缓存，被拦截请求消耗的输入也按型号计入费用。
  - **本地补转**（`asr/fallback.py`）：切到最短仍被拦截的区间交给本地模型补转（`[asr] fallback = "auto"`：只有中文时 Paraformer，其他语言或多语混合用 Qwen3；`"none"` 不补转），时间换算回整节课后与大模型结果按时间合并。补转只是尽力而为：方案写错、没装本地依赖、显存不足时保留缺口，在处理记录里注明区间和原因，不中断整个流程。
- **显存**：6GB 显存放不下几个模型同时加载。后端提供 `close()` 释放显存，依次运行多个方案时逐个加载、用完就释放。

## 5. 文档处理

- 课件和资料共用一套"拆页"逻辑：PDF 直接处理（从内存打开，文件损坏时也不会占着文件句柄）；PPTX/DOCX 先经本机 Office（COM）转 PDF；照片按长边缩放到 2000 像素，同一文件夹里的几张照片合成一份 PDF；TXT/MD 不限于 UTF-8（自动识别 GBK、CP949 等），较长时按段落拆成每页约 3000 字。
- 常见但不能直接读取的格式（韩文 HWP、Keynote、Pages、Excel、WPS、CAJ）给出转换提示，其余未知格式跳过并说明原因。
- COM 注意事项（均已实测）：
  - 不调用 `CoUninitialize`：pythoncom 导入时对主线程的初始化不计入引用计数，配对调用会让本线程后续 COM 调用失败。
  - 退出 Office 前先释放文档对象。
  - PowerPoint 是单实例程序，用户自己还开着别的演示文稿时不能退出。
- 页面图片按需发送（有嵌入图片、文字过少或像公式的页面），控制 token 开销。

## 6. 授课语言、现场翻译与全中文输出

- **授课语言不写死**（M3）：课程设置包括学科、授课语言（任意 ISO 639 代码，老师混用几种语言时用逗号分隔，如 `ko,en`）和现场翻译成的语言（可选）。语言名称表放在 `course.py` 一处，表里没有的代码照样可用、直接显示代码。旧写法 `ko+zh` 迁移时换算为"授课 ko、翻译成 zh"，命令行仍接受这种写法。
  - 课程表单（M4 修订）：中文、韩语、英语、日语直接勾选（勾几个表示老师混用几种语言），其他语言填代码；现场翻译用下拉选择。用户不用记语言代码。
- **分析结果全中文**（M4 修订，用户定的原则）：笔记、知识点名称、课程记忆、总复习、考前报告、问答一律用中文。
  - 笔记语言不再是课程选项：`CourseSettings.note_language` 固定为中文，书库里旧的其他取值读出时也按中文。
  - 术语规则（`CourseSettings.term_rule`，整理笔记、整合课程记忆、总复习、问答的提示词共用）：一律用中文书写，不在括号里附韩语、英语等原词；DNA、PCR、ATP 这类通用缩写和符号照常用；人名、学名有通用中文译名的用译名。外语授课时，老师用外语讲的术语要译成准确的中文。
  - 外语原词只写进知识点别名（整合步骤输出的 `aliases`），用于对照外语出的考题和问答检索；界面和导出只显示中文的别名（`render.zh_aliases`）。
  - 保存前再清理一次（`textnorm.strip_foreign_asides`）：笔记（标题、大纲、知识点名称和要点、例题、作业、原话的中文意思）、整合结果（新知识点名称、章节、跨讲联系说明）、总复习要点、问答回答保存前，去掉括号里只有外语的旁注。具体是：全是韩文的；英文单词或短语（含 3 个字母以上、大写字母少于 2 个的普通单词）；中外文混排的括号按「、，；」拆开，去掉只有外语的条目（「称 eclipse」「英文：virus」这类也算）。DNA、mRNA、HDV 这类缩写，单个字母的选项，带数字、中文的括号，公式、代码和 Markdown 链接都保留。原话 quote 是证据，不动。
    - M4 验收：只靠提示词时，病毒学第 1 讲的笔记仍有 21 处英文括注；收紧提示词（写明老师直接说的英语也不括注，并给出例子）后降到 4 处，另有 7 个韩文字符；清理后括注只剩「（HIV）」这类缩写。
    - 不在括号里、讲解词源或术语对照时提到的外语词保留，例如「由 virulent 演变而来」「蓝细菌过去在韩国称「남조류」」：外语词本身就是讲解的对象，删了意思就不完整。
  - 取代了 M4 第十一节的"术语写成「中文（韩语原词）」"。
- 提示词按课程设置填写占位符（`{{subject}}`、`{{teaching}}`、`{{note_language}}`）。缺少取值时直接报错，避免把占位符原样发给模型。
- 转写送给模型时每句带语种标记（`[S12][03:14][ko]`）。有现场翻译时附加一段说明（语言名称和标记按课程设置填入）：授课语言的句子是老师原话，紧随其后的翻译语言句子是翻译，两者合并成一条记录；quote 优先引用原话；判断考试信号以老师原话为准。
- quote 始终保持转写原文，不翻译，这样原话校验才能成立。
- **外语授课：用原文理解，用中文总结**（M4）：
  - 转写、课件识别、资料拆题都保持原文，模型直接读原文整理，不先翻译；
  - 原话逐字保留原文，模型另给出中文意思（`Signal.meaning`，存在 signal 表的 meaning 列）。阅读页、总复习、问答出处先显示中文意思，原文收起、点开可核对（`render.quote_html`，网页和导出的 Markdown 共用）；问答引用链接的悬停提示只写中文意思。给模型的输出结构里它是必填项；M4 以前保存的笔记没有这一项，读出时为空；
  - 有现场翻译时，翻译只用来帮助理解听不清的原话；翻译常有删减或误译，与原话不一致时以原话为准；
  - 问答一律用中文回答（用原文提问也一样），正文不抄写原话，只写证据编号。

## 7. 书库与处理流程

- **结构**：一门课是一本书，一讲是书里的一章；一讲可以由多节录音录像组成（如第 1 讲由 1.1、1-2、1-3、1-4 多个录像合成），处理时合并成一讲。
- **书库**（`library.py`，SQLite；表结构与迁移在 `library_schema.py`）：
  - 课程：学科、授课方式、课程专用转写方案、课程提示词（用户的补充要求，上限 4000 字）、书架顺序（笔记语言一列保留但固定为中文）。
  - 讲：讲次、标题、类型、各节文件（`lecture_part`，只记录路径不复制）、时长、各步骤进度、标签（`lecture_tag`）。
  - 内容表：转写句子（编号全讲连续，与笔记里的 S 编号一致）、课件页、笔记 JSON、考点信号及其校验结果、模型调用记录（按讲或按课程记账）。
  - 课程记忆与总复习的表见第 11、13 节。
- **迁移**：按版本逐段执行固定 SQL（每段自带事务），每次升级前先把数据库备份为 `lecture.db.bak-v<旧版本>`。v2 把旧的单一媒体路径改写成第 1 节后删掉该列（SQLite 3.35 起支持 `DROP COLUMN`）。v3（M3）把 `ko+zh` 拆成授课语言和翻译语言两列，加上课件选择、课程资料、每讲对应的课件页、笔记所用课件页的快照、考前报告和后台任务，删掉 v1 每讲一份课件的 `slides_path`。
- **处理流程**（`pipeline/run.py`）：抽取音频 → 转写 → 匹配课件 → 整理笔记 → 校验原话 → 整合课程记忆 → 上架。整理笔记之前有**考试方案关卡**：方案必须已确认或已跳过，还没有方案时先从来源讲分析、停下等用户确认（见第 26 节）。
  - **课件关卡**：开始分析前，课程必须先选择是否提供课件（`course.slides`：还没选择 / 不提供 / 已提供）。还没选择时 `lec run` 拒绝开始并说明两种做法；导入课件类资料后自动变为已提供，删光后回到还没选择。
  - 课件在转写之后匹配，转写不再依赖课件：之后再导入课件，只需重新匹配和整理笔记，不用重新转写。转写热词取整门课课件术语里出现页数最多的前 150 个。
  - 每步完成后把状态（完成 / 跳过 / 失败 / 待更新）、时间和说明写进书库；失败时记录原因再抛出，下次从失败的步骤继续。
  - **按依赖重跑**（`STEP_DEPS`）：某一步在本次运行中重跑了、而且结果有变化，依赖它的步骤才跟着重跑。例如重新匹配课件的结果与现有笔记所用的页相同，就不重新整理笔记。
  - `--force <步骤>` 强制重跑该步骤及依赖它的步骤；`lec run 课程`（不带讲次）按讲次依次处理所有没完成的讲。
- **多节**：
  - 每节单独抽成 `parts/part-K.wav`；源文件指纹（路径、大小、修改时间）没变就不重新抽取。
  - 逐节转写，按各节时长偏移拼成整讲统一时间轴；整理笔记时在每节开头插一行「—— 第 K 节 ——」。
  - 分片缓存按节判断是否作废：每节的 manifest 记录源文件指纹和热词，只有它们变了才清这一节的缓存。追加一节时，前面已转写的节不会重新转写。
  - 热词的顺序必须与进程无关（同一页的术语按页内顺序去重）。M4 验收发现：原来遍历集合，顺序随字符串哈希的随机种子变化，后台任务每次都在新进程里运行，重新提交失败的处理任务时缓存都被当成热词变了而作废，已转写的片段全部重新请求。
  - `--force transcribe` 保留仍然有效的缓存，只重新请求没有结果的片段（例如此前被拦截、由本地模型补转的片段，配了 `llm_alternates` 后会换型号重试）。要完全重新转写，删掉 `data/work/lecture-N/asr`。
- **转写方案的优先级**：命令行 `--asr` > 课程设置 > `config.toml` 的 `[asr]`。
- **自动**（M4 修订，新书库的默认值）：`auto` 按课程的授课语言选本地模型，只有中文用 Paraformer，含韩语、英语等用 Qwen3-ASR（52 种语言），由 `asr.resolve_spec` 在转写前换成具体方案。方案不支持课程录音里的语言时拦下并说明：Paraformer 只认中文，SenseVoice 认中、英、日、韩、粤。课程设置保存时检查（网页和命令行共用 `asr.language_problem`），开始转写时再检查一次（设置页的默认方案可能与课程语言不符）。M4 验收前新书库默认用 Paraformer，新建韩语或英语课不改设置就会按中文转写。
- **漏转提醒**：转写里超过 2 分钟没有内容（含开头和结尾）时，在处理记录里提醒。大模型转写的时间戳由模型估计，靠这一条兜底。
- **移动讲**（`pipeline/organize.py`）：把放错课程的一讲移到正确的课程。按两门课的设置差异决定从哪一步重跑（授课方式不同重新转写；学科或提示词不同重新整理笔记；都相同只重新整合）；两门课的课程记忆都回到移动位置之前的一致状态，其后整合过的讲标记为待更新；导出文件夹随之移动。

## 8. 原话校验

考点信号的 quote 必须真实出现在转写里，归一化后（去标点空白、统一全角半角）分三级匹配：

1. **window**：在引用的句子范围内（前后各放宽 1 句）拼接后做子串匹配。模型常把相邻几句短句拼成一条引用。
2. **fuzzy**：同一范围内模糊匹配，`partial_ratio ≥ 85`，容忍个别字不同。
3. **global**：在全文中查找，找到就把出处改成原话实际所在的句子。

只有「跳过的课件页」允许不带原话，以课件页码为证据。未通过的信号仍然保留并标记，M3 打分时不计入。

## 9. 导出与网页书架

- **导出**（`books.py`，`schema_version: 3`，每次上架整门课一起重写）：
  - `data/books/<课程>/book.json`：整本书——课程设置、各讲目录（节、时长、标签、状态）、知识点体系（每个知识点在各讲的角色和时长、信号统计）、跨讲联系、总复习、课程资料、考前报告列表。
  - `第NN讲/lecture.json`：一讲的笔记、考点信号（含校验结果、所属课程知识点）、逐句转写、各节信息（含在整讲时间轴上的偏移）、笔记里 P1、P2… 对应的课件页和当前匹配到的页、与课程知识点的对应、跨讲联系、处理记录。M1 的旧 `book.json` 在重新导出时删除。
  - `笔记.md`（含「与前几讲的联系」，课件页码附出处）、`课程总览.md`、`总复习.md`、`考前报告-时间.md`：便于直接阅读。
- **网页书架**（`web/`，FastAPI + Jinja2，无需前端构建）：
  - 首页：一个书架放全部课程，每门课一本书，显示讲数、总时长、各状态数量和复习进度；可按自定义顺序（上移、下移）、最近更新、名称排列。
  - 课程页：各讲目录（可按标签筛选）、按章节分组的知识点体系（出现的讲次可点击跳转、信号统计、重要程度、复习勾选）。
  - 讲的阅读页：大纲、与前几讲的联系、知识点卡片（标出首次讲或深化、回顾，链接到其他讲）、例题、考点信号表、转写全文（标出各节分隔）、标签与移动、处理记录。
  - 总复习页：见第 13 节。
  - 课程资料页（题目和条目、对应的知识点、各页标题，点开看页面图片）、考前报告页（可打印成 PDF、下载 Markdown）、后台任务页（见第 18、19 节）。
  - 播放器跨节播放：点时间戳按偏移找到对应的节，切换文件后定位；一节放完自动接下一节；`?t=毫秒` 深链接用于跨讲跳转。
  - 多节的讲在页面上是一个整体（M4 验收）：浏览器自带的控件只显示当前这一节的进度，所以改用自己的控制条——整讲一条进度条和整讲时间，拖到哪里就换到对应的文件；倍速、静音换节时保持；录像可以全屏。转写全文连续显示，不插分节线。只有一节的讲，以及还有节的时长未知（抽音频之前）的讲，仍用原生控件。
  - 媒体接口按讲和节的编号提供文件，支持 HTTP Range，录像可以拖动进度；M1 的旧地址 `/books/{id}` 重定向到 `/lectures/{id}`。
- **M4：命令行能做的事都搬进了界面**（写操作分在 `web/actions.py`、`manage_courses.py`、`manage_lectures.py`、`settings_page.py`、`qa_page.py`，表单读取和校验都在 `forms.py`）：
  - 书架：新建课程（学科、授课语言、现场翻译、转写方案、课件、课程提示词）。
  - 课程页：处理所有没完成的讲、重建课程记忆、添加一讲（多个文件作为各节，可附一份固定对应的课件、添加后立即处理）、导入资料（文件、文件夹或压缩包）、继续处理资料；课程设置页改设置后提示要从哪一步重做，可一键按新设置重新处理；删除课程要输入课程名确认。
  - 讲的页面：处理或从某一步重做、就这一讲提问、改标题日期和类型、追加一节、手动指定课件页或恢复自动匹配、删除一讲（勾选确认）。
  - 课件关卡：课程还没选择是否提供课件时点「处理」，弹出选择框：导入课件后接着处理（同一条队列，先导入再处理），或声明没有课件后直接处理。
  - 课件页图片在页内弹窗查看；顶栏显示进行中的后台任务数；任务页可以暂停、继续、取消、重试任务，顶部有全部暂停 / 全部继续 / 全部重试；页面上的任务显示进度，结束后自动刷新（页面上有没提交的输入时只提示，不刷新）。
  - 本机路径：桌面程序里用原生对话框选择；在浏览器里打开书架（`lec serve`）时没有对话框，手动粘贴完整路径。
  - 提示：操作结果（如"已删除"、测试连接的结果）在下一个页面顶部显示，存在应用状态里，不放进网址。
- **渲染安全**：
  - Markdown 渲染禁用原始 HTML，模型输出里的 HTML 会被转义。
  - 公式先替换成占位符，避免 `*`、`_` 被当成强调，渲染后再转义放回，由浏览器端 KaTeX 渲染页面的 `<main>`（讲的阅读页、总复习、考前报告、问答、资料页）。离线时公式显示为 LaTeX 原文。

## 10. 安全与隐私

**威胁模型**：个人本地工具，只有本机的网页服务，没有多用户。主要风险是密钥泄露、课程内容外泄、处理不可信文件，以及浏览器里打开的其他网站借用户的浏览器访问本机书架（跨站请求伪造、DNS rebinding）。

**安全决策**：
- 密钥（M4 起）优先从 Windows 凭据管理器读取（keyring，服务名 `lecture-analyzer`，按变量名存，只有当前 Windows 账号能读），没有时用环境变量 / `.env`（`api_key_env` 只存变量名）。设置页只显示"已设置 / 来源"，从不回显；保存时写进凭据管理器，`.env` 里同名的旧值清空；"把 .env 里的密钥移到凭据管理器"由用户自己点。测试用内存里的测试替身，任务子进程用空的凭据管理器，不碰本机真实凭据。`.env` 和 `config.toml` 被 git 忽略，公开仓库里不会出现密钥。
- 设置页改 `config.toml` 时用 tomlkit 保留注释；新内容先写进同一目录的临时文件试读一遍，没问题才替换原文件；只开放页面上的几项，取值都先校验（模型档案存在且能力够、设备写法、语言代码、地址以 http(s):// 开头、不含控制字符）。
- 录音、转写、课件、资料只存放在本地被忽略的目录；只有调用云端模型时，内容才会发给对应服务商，由用户在配置里自行选择。
- 外部程序调用：ffmpeg 用参数列表调用（不经过 shell）；Office 只以只读方式打开文件，转换完不保存原文件。
- 命令行输出前转义异常信息，避免其中的方括号被当成终端样式。
- 网页书架只监听 127.0.0.1；媒体文件只按讲和节的编号从书库查路径后提供，不接受请求里的任意路径；不提供 API 文档页面。
- **防 DNS rebinding**：用 Starlette 的 `TrustedHostMiddleware` 检查 Host 头，只接受 `127.0.0.1` 和 `localhost`，只读页面也检查，防止恶意网站把自己的域名解析到本机后读走转写和笔记。
- **防跨站请求伪造**：写操作（标签、移动讲、书架顺序、复习进度）都是表单 POST，必须带每次启动随机生成的令牌（`secrets.token_urlsafe`），用 `compare_digest` 校验，不对返回 403。其他网站读不到书架页面，拿不到令牌。
- 表单用标准库 `urllib.parse.parse_qs` 解析，请求体限制 4KB（考前分析表单复选框多，放宽到 16KB、400 个字段）；所有字段先校验（讲和课程必须存在、讲次为正整数且不冲突、标签 1–20 字且不含控制字符、报告用到的讲次、资料和模型档案都存在）再写入或入队；重定向地址由服务端拼出，不使用表单传来的地址。
- **资料导入**（`archive.py`）：压缩包里的路径一律去掉盘符、开头的斜杠和 `..`，替换 Windows 不允许的字符和保留名（`CON` 等），只写到暂存目录之内（防 zip slip）；限制文件数（2000）和解压后总大小（4GB）；有密码的压缩包直接报错；rar/7z 用本机 7-Zip 或 UnRAR 以参数列表调用，标准输入接空设备（有密码时直接失败而不是等待输入），解出后删除符号链接和跑出暂存目录的条目。导入的文件复制进 `data/materials/<编号>/`，文件名经过同样的清理。
- 资料页面图片只按资料编号和页码从资料目录取，不接受任意路径；后台任务的结果地址由服务端生成。
- 书库的 SQL 一律用参数绑定；可修改的字段（讲、课程）各用一条固定语句，只允许白名单字段；迁移 SQL 是固定文本。
- 课程提示词由用户自己提供，作为"用户的补充要求"附加到提示词里，并说明与格式要求冲突时以格式要求为准（例如 quote 仍须逐字照抄）。

- **M4 新增的写操作**同样经过 `forms.py`：令牌、大小和字段数限制（多个路径、课程提示词的表单放宽到 64KB）、先校验再写入或入队。本机路径必须是存在的绝对路径（媒体只接受文件），每行一个，去掉资源管理器复制路径时带的引号。删除讲、课程和资料之前检查这门课没有没结束的后台任务。
- **桌面程序的 JS 接口**（`desktop.py` 的 `DesktopApi`）只开放选文件、选文件夹、在资源管理器里打开文件夹（只接受已存在的文件夹，不打开文件，免得运行程序）和首次设置；下划线开头的属性不暴露给网页。网页内容来自本机书架，模型输出渲染时禁用原始 HTML。
- **后台任务的子进程**：命令行由执行器拼出（`python -m lecture_analyzer.worker <配置文件> <任务编号>`），参数是列表、不经过 shell；取消时用 `taskkill /T` 结束整个进程树。

**安全边界**：用户在命令行或界面里选的本地文件视为可信输入（书架只监听本机、写操作要带令牌，路径是使用者在自己电脑上选的）。安全扫描器的"路径遍历"规则只要一行里出现 `Path(`、`read(` 之类后面又有 `args`、`params`、`request` 之类的词就会报，以下几处都属于误报：实验脚本按用户给出的路径读文件；导入资料任务按（已在网页入口校验过的）路径导入；任务子进程读取执行器传来的配置文件路径；`threading.Thread(..., args=...)` 和 `def delete_thread(request, ...)` 这类写法。

**已知风险**：
- 用 Office 打开来源不明的 PPTX/DOCX 时，存在 Office 自身的风险（宏默认禁用）。
- 云端模型服务商的数据保留政策以各家条款为准。
- 本机上的其他程序可以直接访问 127.0.0.1 的书架（读取页面后也能拿到令牌）；个人电脑上视为可接受。

## 11. 课程记忆（L2）

- **两步走**：第一步（整理笔记）只看本讲；第二步（整合，`pipeline/integrate.py`）把本讲笔记归并进整门课的知识点体系。修正某一讲后，只需从这一讲起重新整合，不必重新整理后面各讲的笔记。
- **数据**（`knowledge.py`）：
  - `knowledge_point`：课程知识点，按章节分组（只分"章节 → 知识点"两层）；`key` 是课程内编号（提示词里的 `K12`）。
  - `kp_lecture`：本讲笔记第几个知识点对应哪个课程知识点，角色（首次讲 / 深化 / 回顾 / 应用）和讲解时长。
  - `kp_signal`：考点信号归属的课程知识点，供 M3 打分。
  - `kp_reference`：跨讲联系（回顾 / 承接 / 对比 / 再次强调），附本讲出处句子和一句话说明。
  - `integration_log`：每讲解析成课程内编号后的整合结果。
- **分工**："模型判断、代码校验"。模型输出本讲每个知识点对应哪个 K 编号（或 new）、每条信号属于哪个知识点、有哪些跨讲联系；代码（`resolve`）补全缺漏、纠正无效编号（不存在的 K 编号、与已有名称或别名相同的"新"知识点会并入已有知识点）、按笔记顺序分配新编号、只保留指向更早讲次的联系，并纠正讲次。
- **确定性**：L2 完全由各讲整合结果按讲次顺序叠加而成。对已有知识点只补别名（沿用最早的规范名称），章节为空时才补。所以清空后按讲次重放整合日志，得到的结果完全一样，不需要调用模型。
- **推进规则**（`integrate_through`）：整合第 N 讲时，从头重建——前面一直是最新的讲直接重放日志；从第一讲需要整合的讲起，到第 N 讲为止逐讲调用模型（顺带补做中间待整合的讲）；第 N 讲之后整合过的讲标记为"待更新"，`lec rebuild` 或再次 `lec run` 时重新整合。
- **`lec rebuild 课程 [--from N]`**：不带 `--from` 从第一讲需要更新的讲开始；带 `--from` 从第 N 讲起重新整合。执行前提示要调用几次模型。

## 12. 按上下文预算组装输入（`pipeline/memory.py`）

- token 按"字数 × 档案的 `tokens_per_char`"估算（M0 实测）。输入预算 = 上下文上限 − 输出上限 − 4000 余量，再受 `[memory]` 里的上限约束（默认 6 万，128K 上下文的模型也放得下）。
- **整理笔记**：整讲放得下（输入在预算内，且按 0.35 倍估算的输出不超过输出上限）就一次整理；放不下先按节切，单节仍放不下再按句子对半切，最后把相邻的段尽量合并。各段由代码合并：大纲、例题、作业、信号按顺序拼接，同名知识点合并要点、出处和时长。这样 128K 上下文、8K 输出的模型也能处理 3 小时的课。
- **整合与总复习**：输入分成几部分，各有裁剪顺序；超出预算时按"裁剪顺序、条目重要性"从低到高逐条精简或删除，必带的部分不裁剪，全部裁完仍超出就报错提示换用上下文更大的模型。整合的裁剪顺序：最近几讲的笔记摘要 → 相关历史原话（先删强度低、讲次早的）→ 非候选知识点的要点说明（只保留名称）→ 回顾线索句。处理记录里注明精简了什么。
- **候选知识点**：本讲知识点和信号的名称与已有知识点的名称、别名做模糊匹配（`partial_ratio ≥ 60`，每个名称取前 5 个），再加上一讲的全部知识点。回顾线索句由代码在转写里按课程语言找"上次、讲过、지난번、배웠던、last time、前回"等说法（`course.RECAP_CUES`，可扩展；没有词表的语言照常运行，只是少这一路线索）。

## 13. 总复习（`pipeline/review.py`）

- **复习讲义**：`lec review 课程` 按章节逐章调用模型。模型只写每个知识点合并各讲后的复习要点，并在 `sources`、`emphasis`、`examples` 字段里用编号引用依据（讲解 `L讲次N序号`、原话 `Q`、例题 `E`）；代码丢弃无效编号，模型漏写的知识点用各讲笔记原文补上。
- **正文里不留编号**（M4 验收）：页面和考前报告都不显示这些编号，可模型常在正文里写「（见 Q6、Q7）」「（Q7，重点）」。提示词禁止这样写；保存前再清理一次（`textnorm.strip_citations`）：括号里引用本章输入编号的条目去掉，其余条目保留（「（Q7，重点）」→「（重点）」）。只认本章确实给过的编号，「雌二醇（E2）」这类写法在没有这个编号时保留。要点开头重复知识点名称的标题也去掉：标题就是名称（不看括号），或名称是「标题的……」；「**噬菌体药物**」对「噬菌体药物与噬菌体裂解酶」这类小节标题保留。
- **原话不由模型写**：讲义里的老师原话和出处由代码按编号从书库填入，只来自通过校验的考点信号，并列出这个知识点全部通过校验的原话（模型引用的排在前面）。
- **重要程度由代码计算**："模型抽信号、代码打分"。3 星：有提示考试或考试范围信号、强度 3 的强调，或出现在往年真题、模拟题、复习提纲里（M3）；2 星：有强调或易错信号，或在 2 讲以上出现；1 星：其他；老师明确说不考（强度 3）或考试通知说不考、且没有说要考的单独标出并排在最后（规则与打分相同，见第 17 节）。往年题不能推翻今年"不考"的说明。
- **按考试方案编写**（v0.2.0）：有已确认的考试方案时，系统提示词附上方案和"名词解释写成定义、简答写成分点、论述写成提纲、病例分析写出依据和治疗"等要求，本章知识点行附「适合题型」（各讲笔记里按方案标注的题型）。方案进入章节指纹，改了方案相关章节自动标为待更新；没有方案时提示词和输入与原来完全相同，已生成的章节不会因为升级而变成待更新。
- 每个知识点下列出在课程资料里出现的题目或条目（只用与当前课程记忆一致的对应关系）。`lec review` 生成前先更新过期的对应关系。
- **增量更新**：每章按未裁剪的材料（含提示词）算指纹，材料没变的章节不重新生成；变了的章节在网页和 `总复习.md` 里标为"待更新"。`--all` 全部重写。
- **复习进度**：知识点上勾选"已复习"，按归一化的规范名称记录（`kp_review`），用名称或别名匹配，课程记忆重建后名称不变的知识点进度保留。课程页、复习页和首页书架显示进度。
- **例题归属**：例题按句子编号归到离得最近的知识点（区间重叠为 0，否则取端点距离）。

## 14. 课程资料库（`materials.py`、`archive.py`、`pipeline/ingest.py`）

- **定位**：工具不针对某几门课。课件和资料可以是每讲一份、每章一份（跨好几讲）、整门课一份或一讲好几份；导入文件、文件夹或压缩包都行。
- **类型**：课件 slides、教材 textbook、其他文档 other（按页匹配到各讲）；往年真题 past_exam、模拟题 mock_exam、习题 exercise、复习提纲 review_outline、考试通知 notice（拆成题目或条目，对应到课程知识点）。
- **导入**：每个文档成为一份资料，复制进 `data/materials/<编号>/`（原文件移动或删除后仍可用）；按自然顺序排列（`ch2` 在 `ch10` 前，`第二章` 在 `第十章` 前，中文数字也按数值比较）。
- **zip 文件名编码**：有 UTF-8 标记或 Unicode 路径扩展字段时直接用；否则取出原始字节，先试 UTF-8，再用 charset-normalizer 在 GB18030、CP949、Shift-JIS、Big5 里选最可信的（实测中文、韩文、日文文件名都能区分）。rar、7z 的文件名本来就是 Unicode。
- **拆页与识别**：拆页在本机完成，页面图片存为 `pages/<页码>.png`，文字存为 `pages.json`；逐页识别（`[steps] page_digest`）按批并发（`[materials] digest_workers`，默认 4 路，每批 6 页），每批完成就写入书库：中断后再运行只识别没识别的页；某批失败时其余批次照常保存，最后报出第一个错误。
- **命令**：`lec material add 课程 文件... --kind 类型`（导入后立即识别；`--no-process` 只导入）、`list`、`process`（继续处理）、`remove`。

## 15. 课件匹配（`pipeline/slides.py`）

- **输入**：按页的资料里已识别的全部页面目录（`[F文件序号-页码] 页面标题`，标题截到 40 字，几百页也只有几万字）和这一讲转写的均匀抽样（约 1.2 万字）。一次模型调用（`[steps] match`，没写时与页面识别同一档案），输出讲到的页面区间。资料和授课语言可能不同（如韩语授课、中文课件），提示词要求按含义匹配。
- **代码校验**：文件序号和页码必须存在，起止颠倒时对调，超出范围的截掉；同一份文件里两段之间相隔不超过 3 页时补上中间的页，整理笔记时模型能据此判断老师是否跳过了这些页。
- **兜底**：目录超出预算时，按术语在转写里的命中数逐份去掉最不相关的文件。
- **手动覆盖**：`lec lecture pages 课程 讲次 --pages "3:1-30,4:1-5"`（资料编号:起止页；只写编号表示整份）；`--auto` 取消手动指定。`lec lecture add --slides 文件` 把文件导入为课件并固定对应到这一讲的全部页。
- **整理笔记**：带上匹配到的页面内容，按本讲内的顺序编号为 P1、P2…，括号里注明出处（"资料名 第 N 页"）；总字数超过 6 万时每页按比例截短。整理笔记时把所用的页存成快照（`lecture_note.pages`），之后重新匹配也不会让笔记里的页码错位；网页和 Markdown 按快照显示出处、链接到页面图片。
- **何时重新匹配**：导入或删除课件类资料后，这门课自动匹配（不是手动指定）的讲标记为待重新匹配；重新匹配的结果与笔记所用的页相同时不重新整理笔记。

## 16. 题目与知识点对应（`pipeline/materials.py`）

- **拆题**：按页分批（每批约 2.4 万字）调用模型（`[steps] material`），输出原题号、题型、题干、分值、答案、所在页。跨批的题目：上一批最后一条附在输入末尾，模型把本批开头属于它的部分放进 `continuation_md`，由代码接上。题型是开放的，不在列表里的记为"其他"；考试通知里"要考 / 不考"的说明作为范围声明（`scope_include` / `scope_exclude`）。
- **对应知识点**：给出课程知识点（K 编号）和题目（M 编号，每批 40 条），每条对应 0–3 个，代码去重并丢掉不存在的编号，模型漏掉的题目记为没有对应。对应时记下课程记忆的指纹（知识点编号和名称）；课程记忆变了就算过期，过期的对应关系不参与打分和星级，生成报告或总复习前自动重做。

## 17. 考点打分（`pipeline/scoring.py`）

- 纯代码计算，权重全部可配置（`[scoring]` 只写要改的项），每个知识点都给出分数的构成。
- **课堂**：只计通过原话校验的信号，权重 × 强度（默认：提示考试 5、考试范围 4、强调 3、易错 2、例题 / 推导 / 作业 2、回顾 1、课件外补充 1、跳过的课件页 −1、较弱的"不考" −1）。没有课件的讲不产生「课件外补充」「跳过的课件页」：整理笔记时输入里说明不要输出，整理后再过滤一次（M4 验收：不提供课件的课也标出了 4 条课件外补充）。
- **资料**：每道对应的题目，权重 × 分值系数（默认：往年真题 5、模拟题 4、复习提纲 4、通知 3、习题 2、其他 1）。分值系数 = 题目分值 ÷ 同一份资料里有分值题目的中位数，限制在 0.5 到 2 之间；没写分值为 1。
- **加分**：多在一讲出现 +2、每讲 10 分钟 +1（最多 +3）、复习课里出现 +3、课堂和资料里都出现 +3。有已确认的考试方案时再加「题型匹配」：`question_type_fit`（默认 6）× 知识点适合的各题型在方案里的分值占比之和（最多算 1），题型取各讲笔记里按方案标注的、归到方案题型名称的那些。
- **"不考"**：老师明确说整个知识点不考（信号强度 3）或考试通知写明不考、又没有任何"要考"的说法时，分数清零，单独列出。M3 验收发现，"不用每种都背""这一类不展开"之类的说法（强度 1–2）往往只排除一部分内容，所以只扣分、照常列在"考试范围"里，不整体排除；整理笔记的提示词也说明了"不考"信号的强度怎么定。
- 可以只用部分讲（讲次或标签）和部分资料打分。

## 18. 考前报告（`pipeline/report.py`、`report_input.py`、`report_render.py`）

**原则（M4 修订，用户定的）**：报告直接给出判断后的知识点本身，不给推断过程。M3 的报告主体是排名表（共识分、参考分、各模型名次）、各模型的理由、原话证据、参考分构成、模型分歧和叙述，知识点内容本身反而没有。

- **证据由代码整理并编号**（只给排名用）：原话 Q（只用通过校验的信号，附讲次和时间）、资料题目 M（同一道题对应几个知识点时共用一个编号）、课件页 P（知识点在笔记里标注的页，按快照换算成"资料名 第 N 页"）、例题 E（按句子编号归到最近的知识点）。模型只用编号引用。
- **各模型分别排名**：输入在预算内组装（超出时先精简课件页和例题，再精简资料题目和原话），每个模型输出最可能考的前 N 个考点（`[report] top_n`，默认 15）、理由、预测题型、证据编号。代码只保留有效、不重复、不是"不考"的知识点和存在的证据编号；理由和证据只在后台校验用，不写进报告。某个模型失败时用其余模型的结果并在报告里注明；都失败才报错。
- **按题型分组**（v0.2.0，结果 `version: 3`）：有已确认的考试方案时，排名提示词附上方案并要求每种题型都给出候选；排名个数放大为 max(`top_n`, Σ min(⌈题数 × 1.5⌉, 10))（没写题数的题型算 3 个，最多 40）；知识点行附「适合题型」。模型给的题型归到方案的题型名称，没给时用笔记里标注的。报告先列方案的题型分值表和答题要求，再按每个考点最可能的题型分组（组内保持共识顺序，每组里 ★★★ 展开、其余折叠）；归不到方案题型的放在「其他考点」。多模型排名和 Borda 共识照旧；没有方案时与 `version: 2` 完全相同。
- **共识**：Borda 计数（第 1 名得 N 分，第 2 名得 N−1 分……），同分按程序参考分。
- **知识点要点取自总复习**（`review.update_review_for`）：先把排进报告的知识点所在、需要（重新）生成的章节生成好（没变的章节不调用模型；传给 `generate_review` 的是完整章节列表，只把相关章节标为需要生成，避免误删其他章节），再取这些知识点的复习条目。更新总复习失败时暂用各讲笔记原文，并在报告里注明。
- **报告内容**（结果 `version: 2`）：按共识顺序列出考点，每个只有名称、星级（`kp_priority`，与课程页、总复习同一规则）、可能题型、知识点要点（中文）和"在课程里查看出处"的链接；末尾列出老师明确说不考的知识点名称。要点复制进报告保存，之后总复习更新不影响已生成的报告。报告一律中文，不再有 `[report] language`。
- **旧报告**：M3 留下的报告（没有 `version`）只显示考点名称，注明重新生成可得到知识点要点。报告页可以删除报告（同时删掉导出的 Markdown，更新 book.json）。
- **存储与导出**：`report` 表存整份 JSON；导出 `data/books/<课程>/考前报告-时间-编号.md`，`book.json` 列出报告。`lec report 课程 [--lectures 1,2 | --tag 标签] [--materials 3,4] [--models claude,gemini]`，生成前提示排名的调用次数（每个模型一次）；更新总复习的调用另算。

## 19. 后台任务（`jobs.py`、`job_runner.py`、`job_handlers.py`、`worker.py`）

- 任务记在 `job` 表（类型、参数、状态、进度说明、结果、错误），网页每 2 秒查询 `/api/jobs/{编号}` 显示进度。M4 起任务类型有：处理讲、重建课程记忆、导入资料、继续处理资料、下载本地模型（重任务），考前报告、总复习、问答（轻任务）。
- **每个任务一个子进程**（M4）：`python -m lecture_analyzer.worker <配置文件> <任务编号>`，进度和结果照旧写进任务表。转写占满显卡甚至崩溃都不影响界面；每个任务结束后显存全部释放；子进程重新读取配置和密钥，设置页的修改对下一个任务立即生效。用 `pythonw` 启动的桌面程序里子进程不弹控制台窗口。
- **两条队列**：重任务一个个排队执行，轻任务另开一条，不会被正在跑的转写挡住。排队以任务表为准：提交时只唤醒队列，队列线程从表里取最早的排队任务。同一门课、同一类型、同样参数的任务还没结束时，再次提交直接转到那个任务。
- **状态只单向变化**（唯一的回退是「继续」：已暂停 → 排队中）：排队中 → 进行中 → 完成 / 失败 / 已取消，每次修改都带当前状态的条件；取消之后子进程再写回的进度和结果都不生效。"开始执行"和"取消"在同一把锁里完成，不会出现标了取消、进程却没被结束的情况。
- **取消**：排队中的直接标为已取消；进行中的先标记，再用 `taskkill /T` 结束整个进程树（含 ffmpeg 等）。已完成的步骤和已识别的页都是断点，再次提交会接着做。
- **暂停 / 继续**：排队中或进行中 → 已暂停（进行中的同样结束进程树，之后子进程写回的进度和结果不生效）；继续时改回排队中，按原编号排队，从断点接着做。书架重启后已暂停的任务保持暂停（不标为失败）。暂停的任务仍算没结束：删除讲、课程、资料前同样要先继续完成或取消。
- **重试**：失败或已取消的任务按原来的课程、类型和参数提交一个新任务（旧任务保留，看得到失败原因；同样的任务已在排队时直接用那个）。「全部重试」对同一门课、同一类型、同样参数的任务只看最新的一个，后来已经重新提交并完成的不再提交。
- **崩溃**：子进程没写结果就退出时标为失败，附上退出码和日志（`data/work/jobs/job-编号.log`）的最后几行；只保留失败任务的日志。
- **关闭**：书架关闭时结束所有子进程，任务标为失败（"在完成前被关闭"）；启动时把上次没执行完的任务标为失败。
- **并发写书库**：界面和任务子进程同时读写书库，书库改用 WAL 模式（读写互不阻塞），写入遇到对方正在写时最多等 30 秒。调用模型（可能几分钟）时不能有没提交的写操作，测试里的假模型会检查这一点。
- 进度更细：大模型转写报告"转写：第 3/18 片"；整合课程记忆报告"整合课程记忆：第 N 讲…"；下载本地模型按目录大小估算百分比。处理多讲的任务在进度前加"第 N 讲 · "。

## 20. 流式请求（`llm/openai_compat.py`）

- **临时错误重试**（`base.retry_transient`）：最多重试 3 次（间隔 5 秒、20 秒、60 秒），仍失败时提示稍后重新提交（已完成的部分不会重做）。重试只做这一层：创建 SDK 客户端时设 `max_retries=0`，否则两层相乘。
  - 连接中断（含超时）：流式请求读到一半断开时 SDK 不会自动重试，还可能直接抛出底层 HTTP 库的传输错误（实测 `RemoteProtocolError`）。openai 3.x、anthropic 1.x 的 SDK 改用 `httpx2`，它的异常不是 `httpx` 异常的子类，M4 验收时按 `httpx` 判断漏掉了一次 Claude 的断线，所以两个适配器按 `httpx2.TransportError` 判断。
  - 服务端暂时不可用：状态码 408、409、429、500、502、503、504、529。M4 验收实测中转站号池容量不足（503 No capacity available）要等几十秒才恢复，SDK 自带的快速重试（约 2 秒内两次）不够，问答任务因此失败。
  - 流式请求卡住：读取超时按"多久收不到任何数据"算，默认 300 秒（档案选项 `stream_idle_s`），非流式请求仍是 `timeout_s`（默认 600 秒）。M4 验收：中转站接受了请求却一直不返回，每次都等满 600 秒，加上 SDK 和外层的重试，一个 2.5 分钟的转写片段卡了一小时。
  - 缺少密钥时三个适配器都提示去设置页填写（`ModelProfile.required_api_key`），不再显示 SDK 的原始报错。
  - 各家 SDK 的其他接口错误统一转成 `LLMError`，命令行和任务页显示说明而不是堆栈。
- 中转站前面有 Cloudflare，非流式请求超过约 120 秒才开始响应会返回 524。档案选项 `options.stream = true` 时改用流式：一律用 `stream=True` 自己累积数据块，用量通过 `stream_options.include_usage` 取得；截断、内容过滤、空结果的处理与非流式相同。
- **严格 JSON Schema 不用 SDK 的 parse / stream 辅助方法**：请求里照样发送同一份严格 schema（`type_to_response_format_param`，服务端约束不变），返回的文本交给基类解析（兼容 ```json 代码块和前后多余文字，不合格时带修正提示重试一次）。M4 验收实测：Gemini 偶尔在 JSON 前面套上 ```json，SDK 的 stream 辅助方法逐块解析，在第一个字符就报 `expected value at line 1 column 1`，整片转写失败。
- 实测：中转站边生成边转发（一次 31.6 秒的请求，第一个数据块在 5.0 秒到达，共 160 块），文本、结构化输出、音频输入都正常返回用量。

## 21. 问答（`pipeline/qa.py`、`conversations.py`、`web/qa_page.py`）

- **检索**（`[steps] qa_retrieve`，默认与课件匹配同一档案）：输入课程知识点目录（编号、名称、章节、别名、出现的讲、在资料里对应的题目）、各讲大纲和最近 3 轮对话，输出相关知识点（最多 8 个）和针对整讲提问时的讲次；只保留范围内存在的编号。目录里附上资料题目的编号，问"模拟题第 3 题"也能找到对应的知识点。
- **证据**（代码整理）：沿用考前报告的编号（原话 Q、资料题目 M、课件页 P、例题 E，只用所选范围里的），另加笔记要点 N 和转写片段 T（知识点开始讲的地方，从前一句起取约 800 字，带时间）；同一讲同一知识点只编一次号。限定某一讲时只用这一讲的内容，不用资料题目。
- **回答**（`[steps] qa`，默认 Claude）：一律用中文回答，引用证据只写编号，分清老师说的和推断；课程内容里没有的直接说明，不编造；课程之外的补充单独放在 supplement_md。代码只保留存在的编号，结果里只存回答引用的证据。
- **显示**：回答里的 [N1]、[T2]… 渲染成出处链接（原话、转写、笔记、例题跳到录音的时间点，课件页弹出页面图片，题目打开资料页）；只替换文字部分，不动 HTML 标签和属性。
- **存储**：`qa` 表（schema v4）存每轮问答（课程、限定的讲、对话编号、问题、回答和证据的 JSON、模型、时间）；删讲后问答保留（讲的编号置空）。问答作为轻任务运行，页面显示进度，答完自动刷新；追问时带上同一段对话最近 3 轮。

## 22. 设置、密钥与书库位置（`config_edit.py`、`credentials.py`、`apphome.py`、`web/settings_page.py`）

- 设置页：各模型档案的型号和接口地址（档案设置了 `model_env` / `base_url_env` 时写进 `.env`，否则写进 `config.toml`）、密钥（凭据管理器）、测试连接（发一个很短的请求）；各步骤用哪个模型（只列出能力够的档案）；转写方案（含"自动"）、本地模型的预设和型号、设备（auto / cuda:0 / cpu）、本地模型位置和下载状态；资料识别并发数；费用统计。第一次使用时（`?welcome=1`）顶部有填写说明。
- 书库文件夹放 `config.toml`、`.env`、`data/`；桌面程序选定的位置记在 `%APPDATA%\LectureAnalyzer\settings.json`。查找配置的顺序：命令行 `--config` > 环境变量 `LEC_CONFIG` > 当前目录的 `config.toml` > 记下的书库。新建书库时复制示例配置（随 wheel 打包），本地模型默认下载到书库里的 `models`。
- `[asr] device = "auto"`（新的默认值）：有可用的 NVIDIA 显卡就用 cuda:0，否则用 CPU；`[asr] model_dir` 不填时用 ModelScope 默认缓存。

## 23. 本地语音识别模型（`asr/models.py`）

- 各转写方案要用的 ModelScope 模型（含语音活动检测、标点）、是否已下载（snapshots 下有说明文件且没有下载到一半的 `.incomplete` 文件）、下载。下载位置与 FunASR、Qwen3-ASR 自己下载时完全相同（`MODELSCOPE_CACHE` = `[asr] model_dir`），下载过的不重复下载，也可以把 model_dir 指向已有的 ModelScope 缓存。
- 第一次用本地方案转写时先下载缺的模型；也可以在设置页提前下载（后台任务）。下载在后台线程里进行，当前线程每 3 秒按目录大小报告进度（书库连接不能跨线程使用）。
- 模型编号表放在这里（`QWEN3_REPOS` 等），查下载状态时不用导入 transformers。

## 24. 桌面程序（`desktop.py`）

- pywebview（Windows 下是 WebView2）打开一个独立窗口，里面是本机的网页书架；网页服务（uvicorn）在后台线程里运行，只监听 127.0.0.1，直接使用系统分配端口后绑定好的套接字（没有抢端口的空档）。
- 还没有书库时先显示首次设置页（本地 HTML，样式与书架一致）：新建书库（默认"文档\课程书架"）或选择已有的书库文件夹；新建的接着打开设置页填写模型和密钥。
- 同一时间只运行一个书架（命名互斥体），再次启动时把已打开的窗口切到前台；任务栏用自己的应用编号，显示书架的图标。
- 关窗时还有没结束的后台任务，先确认；确认后停止网页服务，后台任务的子进程随之结束。
- 没有 WebView2 运行时的电脑（pywebview 会退回早已淘汰的 IE 内核，页面无法正常显示），按微软文档的方法查注册表，改用系统浏览器打开书架，并提示下载地址。
- 用 `pythonw` 启动时没有控制台，输出写进 `%APPDATA%\LectureAnalyzer\desktop.log`；启动失败时弹出说明。开发时用 `lec desktop` 打开窗口。

## 25. 打包（`packaging/`）

- 不用 PyInstaller 冻结（torch、transformers、funasr 动态导入多，冻结很脆弱），而是"自带 Python 运行时 + 启动程序"：`build.ps1` 复制 uv 管理的独立 Python 3.12 作为 `runtime\`（删掉 `EXTERNALLY-MANAGED`，这是程序私有的运行时），按 `uv.lock` 导出的固定版本装好全部依赖（含 PyTorch CUDA 13.0、本地语音识别）和本项目的 wheel，并预先编译字节码。
- `LectureAnalyzer.exe`：系统自带的 csc.exe 编译的启动程序（`launcher.cs`），用 `runtime\pythonw.exe -m lecture_analyzer.desktop` 启动桌面程序后退出；设置 `PYTHONNOUSERSITE=1`，不读用户目录里另装的 Python 包。`lec.cmd`：命令行入口。
- 7-Zip：用系统自带的 `msiexec /a` 从官方 MSI 解出 `7z.exe`、`7z.dll` 和许可证（不安装），放在 `tools\7zip\`；`archive.py` 先找它，再找本机装的 7-Zip 和 WinRAR。
- 图标：`packaging/make_icon.py` 用 PyMuPDF 把书架的书本标志渲染成各尺寸 PNG，拼成 `app.ico`（ICO 里直接存 PNG），窗口、任务栏、启动程序和网页 favicon 共用。
- 安装包：Inno Setup 编译 `installer.iss`，按用户安装（不需要管理员），默认装到 `%LOCALAPPDATA%\Programs\LectureAnalyzer`；开始菜单有「课程书架」和「课程书架命令行」，桌面图标可选；卸载时保留书库文件夹和记下的书库位置。Inno Setup 6.x 没有自带简体中文翻译，把官方仓库里的 `Files\Languages\Unofficial\ChineseSimplified.isl` 放进它的 Languages 文件夹即可，没有时安装向导用英文。
- `THIRD-PARTY-NOTICES.txt`：由 `notices.py` 用打包好的运行时列出随附的 Python 包和许可证，加上 Python、7-Zip、FFmpeg、CUDA 运行库的说明。

## 26. 考试方案（`exam_plans.py`、`pipeline/exam_plan.py`、`web/exam_plan_page.py`、`cli_plan.py`）

**原则（v0.2.0，用户定的）**：先弄清这门课怎么考，再分析知识点。考核方式、题型分值、老师规定的答题方向由第一讲（或用户提供的考试说明）得出，用户确认后，整理笔记、总复习、打分、考前报告和问答都以它为依据。

- **内容**：考核方式、考试时长、卷面总分、成绩构成（平时 / 期中 / 期末……占比）、题型表（题型、题数、每题分值、说明）、答题要求（可限定题型）、考试范围（要考 / 不考 / 重点）、没有提到的项目。题型尽量归到资料题型（`ITEM_TYPES` 的题型部分，`exam_plans.QUESTION_TYPES` 与它一致，由测试保证），显示时用来源原文的写法（如「A1 型题」）。**合计分值和占比由代码算**：有题数和每题分值时为两者之积，否则用写明的合计；占比按各题型合计之和（都没有时按卷面总分）。
- **来源**（一次模型调用，`[steps] exam_plan` 没写时与整理笔记同一个档案）：用户在课程页填写的考试说明（最可信）→ 考试通知、复习提纲资料的条目 → 往年真题、模拟题、习题的题型统计（只作参考，不能代替今年的说法）→ 来源讲（默认讲次最小的一讲）的转写摘录：开头 `lead_minutes`（默认 40 分钟）一段，加上提到考试、题型、分值、闭卷、平时成绩等关键词的句子前后各 `window_minutes`（默认 2 分钟），相邻的段合并，按预算组装时先去掉关键词少的段，开头一段最后才去。长讲（如 7 小时）也只调用一次。
- **出处与校验**：每一条都带出处。课堂出处的原话按考点信号的三级规则核对（`validate.check_quote`，与信号共用）；编号偏了时按原话实际所在的句子给出跳转录音的时间；核对不上的保留并标「原话未核对上」，由用户确认时判断。提示词要求没有提到的数值填 0、写进「没有提到」，不许猜。
- **状态**（`course.exam_plan`）：未设置 → 待确认（分析或保存过）→ 已确认；任何时候都可以跳过、重新分析或修改。只有**已确认**的方案进入后续提示词（`plan_block`，每一步附上这一步怎么用方案）；草稿、跳过或没有方案时为空字符串，各步骤的提示词与没有这个功能时逐字相同（测试保证）。
- **关卡**（`ensure_exam_plan`，在整理笔记之前）：已确认或已跳过时放行；未设置时，来源讲已转写（或填了考试说明）就先分析、保存为待确认，然后抛出 `AwaitingExamPlan`——这一步不记为失败，后台任务照常结束并转到课程页的方案卡片，命令行提示 `lec plan` 的用法；来源讲还没转写、也没有考试说明时提示先处理来源讲。`process_lectures` 按讲次处理，所以「处理全部讲」会在第一讲转写完后停下。`[exam_plan] auto_confirm = true` 时分析完直接采用、接着处理。
- **修改与确认**（课程页卡片）：表格逐行修改，每行带原来那一条的序号——内容没改的行保留原来的出处，改过或新增的记为用户填写，清空即删除；题型名称留空时按「归类」补上。确认时比较方案指纹（不含出处）和上次确认的：变了且已有讲整理过笔记，就自动提交「从整理笔记起重新处理全部讲」；第一次确认或内容没变时只接着处理没完成的讲。跳过同样只接着处理没完成的讲。
- **其他**：笔记里每个知识点多了 `question_types`（只能从方案题型里选；旧笔记读出时为空列表，分段整理合并时取并集），课程知识点适合的题型按出现的各讲合并（`LectureCache.kp_question_types`）。把一讲移到考试方案不同的课程时从整理笔记起重跑。导出 `考试方案.md`，`book.json` 加 `exam_plan`。数据库 v5：`course.exam_plan` 列和 `exam_plan` 表（来源讲、考试说明、方案 JSON、上次确认的指纹）。
- 命令行：`lec plan show 课程`、`lec plan analyze 课程 [--lecture N] [--text-file 说明.txt]`、`lec plan confirm 课程`、`lec plan skip 课程`。
